Add these new DECLARE variables:
```sql

v_att_engaged         numeric;
v_def_engaged         numeric;
```

Modify the NAVAL PHASE attack/defense summation loops:
```sql
v_att_qty := COALESCE((v_att_units ->> v_unit_type)::numeric, 0);
v_att_engaged := GREATEST(1, FLOOR(v_att_qty * v_engagement_fraction));
IF v_att_qty > 0 THEN
  v_att_naval_attack  := v_att_naval_attack  + v_att_engaged * COALESCE((v_unit_attack  ->> v_unit_type)::numeric, 0);
  v_att_naval_defense := v_att_naval_defense + v_att_engaged * COALESCE((v_unit_defense ->> v_unit_type)::numeric, 0);
END IF;
```

Same pattern for defender naval, attacker land, and defender land loops. The GREATEST(1, FLOOR(...)) ensures at least 1 unit engages when qty > 0.

**Critical: Casualty application uses engaged subset correctly.**
The loss_ratio is computed from engaged totals. Casualties = LEAST(FLOOR(engaged * loss_ratio), total_qty). This ensures:
- Loss ratio reflects the strength of engaged portion only
- Casualties cannot exceed total army (LEAST clamp uses total, not engaged)
- Dead units are subtracted from the full army count

Do NOT change the casualty application loop structure — only the attack/defense summation uses engaged counts. The loss_ratio naturally scales casualties because it's computed from the smaller engaged totals.

**Anti-pattern to avoid:** Do NOT apply engagement fraction in both the summation AND the casualty loops — that double-counts the fraction.
