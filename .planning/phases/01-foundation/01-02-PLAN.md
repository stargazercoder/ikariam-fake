<objective>
Auth system with login/signup screens, Riverpod auth state provider, GoRouter with auth redirect guards, and session persistence across browser refresh.

Purpose: Users must be able to create accounts and log in before any game feature can be used. Auth state drives all routing decisions. Session persistence (AUTH-02) ensures players don't re-login after every page refresh.
Output: Working login and signup screens, auth state management via Riverpod, GoRouter with redirect guards, session persistence verified.

NOTE — Profile update exception: ProfileRepository.updateProfile() uses a direct `supabase.from('profiles').update()` call from the Flutter client. This is a deliberate exception to the "all game mutations go through Edge Functions" constraint. The `profiles` table is a player-preferences table (display_name, avatar_id), not a game-state table. The `profiles_update_own` RLS policy explicitly permits client-side updates restricted to the authenticated user's own row. Game-state tables (islands, cities) have NO client-side mutation policies.
</objective>
