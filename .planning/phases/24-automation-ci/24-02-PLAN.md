  <action>
Create `.github/workflows/` directory and `ci.yml` file with the following exact content:

```yaml
name: CI

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  quality-gate:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Set up Flutter
        uses: subosito/flutter-action@v2
        with:
          channel: stable
          cache: true

      - name: Set up Deno
        uses: denoland/setup-deno@v2
        with:
          deno-version: v2.2.x  # Supabase Edge Runtime does not support Deno 2.3+ lock file v5 (supabase/supabase#33093)

      - name: Install Flutter dependencies
        run: flutter pub get

      - name: Flutter analyze
        run: flutter analyze

      - name: Deno test
        run: deno test supabase/functions/tests/

      - name: Flutter test
        run: flutter test

      - name: Flutter build web
        run: flutter build web --dart-define=SUPABASE_URL=http://placeholder --dart-define=SUPABASE_ANON_KEY=placeholder
```

Key design decisions:
- Single job `quality-gate` on `ubuntu-latest` — single platform (web only), no matrix needed
- `subosito/flutter-action@v2` with `cache: true` — caches pub dependencies for faster runs
- `denoland/setup-deno@v2` with `deno-version: v2.2.x` — pinned per locked decision; inline comment references supabase/supabase#33093
- No Supabase CLI in CI — Deno tests are pure functions, Flutter tests use mocked providers
- `flutter build web` uses placeholder dart-define values — build step is a compile check, not runtime
- Steps are sequential: checkout -> setup -> pub get -> analyze -> deno test -> flutter test -> build web
- Any step failure (analyze, deno test, flutter test) causes non-zero exit and blocks merge
