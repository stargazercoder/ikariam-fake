## Spacing Scale

All values from the 8-point scale. No new tokens are introduced — reuse existing spacing already applied in `building_upgrade_sheet.dart` and `movements_screen.dart`.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | `SizedBox(height: 4)` — gap between unit label row and cargo row in movement card |
| sm | 8px | `SizedBox(width/height: 8)` — gap between icon and label, gap between rows inside dialog content |
| md | 16px | `Padding(all: 16)` — dialog body padding, card padding, list padding |
| lg | 24px | `Divider(height: 24)` — section separator inside TradeDialog |
| xl | 32px | `Padding(all: 32)` — empty state outer padding |
| 2xl | 48px | Reserved (not used in Phase 15) |
| 3xl | 64px | Reserved (not used in Phase 15) |

Exceptions: Touch targets on slider thumb are handled by Flutter's built-in 48dp minimum — no custom override needed.

Source: Verified against `building_upgrade_sheet.dart` padding values (`EdgeInsets.all(20)` on dialog body — round to nearest md=16 token) and `movements_screen.dart` (`EdgeInsets.all(16)` on ListView, `EdgeInsets.symmetric(vertical: 4)` on cards).

Note: `building_upgrade_sheet.dart` uses `EdgeInsets.all(20)` — non-standard. New TradeDialog uses `EdgeInsets.all(16)` (md) to normalize to the scale.

## Typography

Source: `lib/core/theme/app_theme.dart` — Material 3 TextTheme (Roboto). Phase 15 uses the same four roles already established across city and movements screens.

| Role | Flutter TextTheme style | Size | Weight | Line Height |
|------|------------------------|------|--------|-------------|
| Body | `bodyMedium` | 14px | 400 regular | 1.5 |
| Label | `labelLarge` | 14px | 500 medium | 1.4 |
| Heading (dialog title) | `titleLarge` | 22px | 700 bold | 1.2 |
| Sub-heading (section title) | `titleSmall` | 14px | 700 bold | 1.2 |

Two weights in use: **400 (regular)** and **700 (bold)**. `labelLarge` at weight 500 is a Material 3 system default — not a custom declaration.

Apply `fontWeight: FontWeight.bold` to: dialog header city name, resource row labels at zero balance (same pattern as `building_upgrade_sheet.dart` line 180).

## Component Inventory

All components are either reused unchanged, reused with a minor patch, or new and built from existing patterns.

### New: TradeDialog (`lib/features/trade/screens/trade_dialog.dart`)

Entry point: `showTradeDialog(context, originCityId:, destinationCityId:, destinationCityName:)`

Outer shell:
```
Dialog(
  shape: RoundedRectangleBorder(borderRadius: BorderRadius.circular(16)),
  child: ConstrainedBox(
    constraints: BoxConstraints(maxWidth: 420),
    child: _TradeDialogContent(...)
  )
)
```

Content layout (top to bottom, all inside `SingleChildScrollView > Padding(all: 16)`):

1. **Header row** — `Icons.local_shipping` (size 32, color `theme.colorScheme.primary`) + city name in `titleLarge bold` + `Icons.close` button. No subtitle line needed.
2. **Divider** — `Divider(height: 24)`
3. **Travel time row** — `Icons.timer_outlined` (size 18, `Colors.grey.shade600`) + "Arrives in: Xh Ym" in `bodyMedium`. Computed client-side using `calcTravelMinutes()`. Static text (not a CountdownTimerWidget — departure is in the future so the countdown has no meaningful state before sending).
4. **Divider** — `Divider(height: 24)`
5. **Resource sliders section** — Repeating block for each tradeable resource type (wood, marble, crystal, sulfur only — gold and wine excluded; see Copywriting section):

   Per resource row layout:
   ```
   Column(
     children: [
       Row(
         children: [
           Icon(_resourceIcon(type), size 18),
           SizedBox(width: 8),
           Text(resourceName, labelLarge),
           Spacer(),
           Text('${sliderValue.toInt()} / ${senderAvailable.toInt()}',
                color: sufficient ? Colors.green.shade700 : theme.colorScheme.error,
                fontWeight: FontWeight.w600),
         ]
       ),
       Slider(
         value: _sliderValues[type],
         min: 0,
         max: senderAvailable.clamp(0, senderAvailable),
         divisions: senderAvailable > 0 ? senderAvailable.toInt().clamp(1, 500) : 1,
         label: sliderValue.toInt().toString(),
         onChanged: senderAvailable > 0 ? (v) => setState(...) : null,
       ),
       Row(  // Recipient capacity sub-row
         children: [
           Text('Recipient space: ${recipientSpace.toInt()}',
                bodySmall, Colors.grey.shade600),
           Spacer(),
           // Overflow warning chip — shown only when sliderValue > recipientSpace
           if (wouldOverflow)
             Text('Warehouse full', bodySmall, Colors.orange.shade700),
         ]
       ),
       SizedBox(height: 8),
     ]
   )
   ```

6. **Send Trade button** — `ElevatedButton.icon` (full width, height 48, `primaryColor` background):
   - Enabled when: at least one slider > 0 AND no overflow on any selected resource AND `!_isLoading`
   - Disabled state: `null` onPressed — Flutter renders greyed-out automatically
   - Loading state: `CircularProgressIndicator(strokeWidth: 2, color: Colors.white)` replaces icon, label becomes "Sending..."
   - Label when enabled: "Send Trade" (see Copywriting)

7. **Close button** — `OutlinedButton` full width, label "Cancel" (see Copywriting)

Replace the current own-city `context.go('/city')` / enemy `_showEnemyCityDialog()` split with a unified `_showCityActionDialog()` for all occupied slots.

### Tradeable Resource Types

Gold and wine are excluded from the trade dialog:
- Gold is the currency unit and should not be directly transferable between players in v1.2 (avoids exploit vectors).
- Wine is a city-local consumption resource; inter-city wine transfer has no clear game-design value in v1.2.

Tradeable in Phase 15: **wood, marble, crystal, sulfur** (4 resource types).

This is a Claude's Discretion decision (CONTEXT.md: "Claude's Discretion — Exact slider widget implementation"). Decision recorded here for executor and auditor.

### Destructive Actions

No destructive actions in Phase 15. "Send Trade" is irreversible once sent (cargo is in transit) but is not destructive — it is a positive player action. No confirmation step per CONTEXT.md: "Single-step send — fill in resources, tap Send Trade, done. No confirmation step."

## Interaction States

### TradeDialog States

| State | Trigger | Visual |
|-------|---------|--------|
| Initial load | Dialog opens, recipient data loading | Each slider row shows `CircularProgressIndicator(strokeWidth: 2, size: 16)` in place of capacity sub-label while `FutureProvider` resolves |
| Recipient load failed | `FutureProvider` error | Capacity sub-label replaced with "Could not load capacity" in `Colors.orange.shade700`; slider still usable; server validates on submit |
| All sliders at zero | Default / user reset all sliders | "Send Trade" button disabled (greyed out) |
| Slider > recipient space | User drags slider past capacity | Inline "Warehouse full" chip appears in orange; slider value not clamped (server is authoritative); "Send Trade" remains enabled — server will reject if overflow |
| Sending | User taps "Send Trade" | Button shows `CircularProgressIndicator` + "Sending..." label; all sliders disabled (`onChanged: null`); close button disabled |
| Success | Edge Function returns 200 | Dialog pops; SnackBar appears with green background |
| Error | Edge Function returns non-200 | `_isLoading = false`; SnackBar appears with `colorScheme.error` background; dialog stays open for correction |

### Island Screen City Tap States

| State | Trigger | Visual |
|-------|---------|--------|
| Empty slot | Tap on unoccupied slot | No action (existing behavior unchanged) |
| Own city | Tap on own occupied slot | Action dialog with "Go to City" (primary) and "Trade" (secondary) |
| Other player's city | Tap on occupied slot, different owner | Action dialog with "Trade" (primary) and "Attack" (secondary, error-colored border) |
