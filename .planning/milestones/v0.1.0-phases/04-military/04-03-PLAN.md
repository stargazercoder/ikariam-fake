**1. MilitaryRepository (lib/features/military/data/military_repository.dart):**
Mirror BuildingsRepository pattern.
- Constructor takes SupabaseClient
- `Stream<TrainingQueueEntry?> watchTrainingQueue(String cityId)` — .stream(primaryKey: ['id']).eq('city_id', cityId).map to single entry or null
- `Stream<List<CityUnit>> watchArmyRoster(String cityId)` — .stream(primaryKey: ['id']).eq('city_id', cityId).map to List<CityUnit>
- `Stream<List<UnitMovement>> watchOutgoingMovements(String cityId)` — .from('unit_movements').stream(primaryKey: ['id']).map then filter where originCityId == cityId (Realtime stream doesn't support eq on two columns, so filter client-side, or use .eq('owner_id', ...) — actually simplest is to stream all and filter in map since player has few movements)
  Alternative: use supabase .from('unit_movements').stream(primaryKey: ['id']) and filter client-side by checking owner_id matches current user
- `Future<void> trainUnits(String cityId, String unitType, int quantity)` — calls Supabase functions.invoke('train-units', body: {city_id, unit_type, quantity}). Parse response, throw TrainingException on non-200.
- `Future<void> dispatchUnits(String originCityId, String destinationCityId, Map<String, int> units)` — calls functions.invoke('dispatch-units', body: {origin_city_id, destination_city_id, units}). Parse response, throw DispatchException on non-200.
- class TrainingException implements Exception (mirror BuildingUpgradeException)
- class DispatchException implements Exception
- Provider: `final militaryRepositoryProvider = Provider<MilitaryRepository>(...)`

**3. BarracksScreen (lib/features/military/screens/barracks_screen.dart):**
ConsumerStatefulWidget. Receives cityId as constructor param.
- Watches buildingsStreamProvider(cityId) to get barracks level
- Watches trainingQueueProvider(cityId) for active training
- Watches armyRosterProvider(cityId) for current unit counts
- Header section: "Barracks (Level X)" with army roster summary
- If training active: show CountdownTimerWidget with unit type and quantity being trained
- Unit list: ListView of 8 land UnitType values. For each:
  - Show unit name (displayName), required level (unitUnlockLevels), cost per unit (unitBaseCosts), time per unit (unitBaseTimes)
  - If barracks level < required level: show locked icon + "Requires Barracks Lv.{X}"
  - If unlocked: show quantity input (TextField with number keyboard, default 1) and "Train" ElevatedButton
  - If training queue busy: disable all Train buttons
  - Train button onPressed: call militaryRepository.trainUnits(), show SnackBar on error (TrainingException.message), catch and display
- Current army section at bottom: list of owned land units with quantities

**4. ShipyardScreen (lib/features/military/screens/shipyard_screen.dart):**
Identical structure to BarracksScreen but:
- Watches shipyard building level instead of barracks
- Shows 5 naval UnitType values (where isNaval == true)
- "Shipyard (Level X)" header
- Same training queue display and Train button logic
- Current navy section at bottom: list of owned naval units with quantities

**5. DispatchScreen (lib/features/military/screens/dispatch_screen.dart):**
ConsumerStatefulWidget. Receives originCityId as constructor param.
- Watches armyRosterProvider(originCityId) for available units
- State: Map<String, int> selectedUnits (unit_type -> quantity), String? targetCityId
- Target city input: TextField for destination city ID (in v1, player types or pastes the target city ID — full city picker is a v2 enhancement)
  Alternative simpler approach: show a dropdown of cities from the world map that aren't the player's own. Use allIslandsProvider to get all islands, then for each island fetch cities. For v1, just use a TextField for target city ID with a hint "Enter target city ID".
- Unit selection: for each CityUnit with quantity > 0, show a row with unit name, available quantity, and a number input for how many to dispatch (0 to available)
- Travel time display: if target city ID entered, show estimated travel time using calcTravelMinutes (need origin and destination island coordinates — fetch from provider or pass as param). For v1, show "Travel time calculated on dispatch" text since we don't have destination coordinates client-side without an extra fetch.
- "Dispatch" ElevatedButton: enabled only if at least 1 unit selected and target city ID entered. Calls militaryRepository.dispatchUnits(). Shows SnackBar on success ("Army dispatched! Arrives in X minutes") or error.
- Active movements section: watch unitMovementsProvider(originCityId), show each movement with destination, units snapshot, and CountdownTimerWidget for arriveAt.
